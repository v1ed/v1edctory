# MS003 — явный отказ вместо неподдерживаемого GPU исполнения

## Цель

Добавить проверяемый runtime режим, в котором отсутствие реализации не превращается в успешно представленный неполный кадр. Это новая политика; существующий `run --strict` решает другую задачу и не должен переименовываться без анализа совместимости.

## Инвентаризация

Найти пути unsupported shader/instruction, failed PSO, pending asynchronous compilation, skipped draw/dispatch, indirect argument clamping, loop/watchdog budget exhaustion и временные placeholder resources.

Отличать временную неготовность компиляции от окончательного отказа. `PENDING` должен привести к ожиданию/завершению требуемой работы либо диагностической ошибке, а не к потере draw. Корректный API-defined null descriptor не является автоматически ошибкой; требуется сравнение с source contract.

## Поведение

- Реализованная операция исполняется с проверенной семантикой.
- Отсутствующая реализация даёт structured failure с operation/shader identity и причиной.
- Недостоверный fallback не маскируется как successful execution.
- При возможности сохраняются минимальные inputs/state и воспроизводимый trace вне repo.
- Выполненный частичный кадр/работа до ошибки не считается успешным completion.
- Watchdog сохраняется. Исчерпание бюджета не должно выдавать обрезанный результат за правильный; сначала реализовать надёжный сигнал отказа, не удалять защиту.
- Переданное число indirect groups нельзя просто обрезать до host limit. Нужна эквивалентная реализация или отказ.

Не требуется реализовать все неподдерживаемые shaders в этой задаче. Требуется сделать ограничение видимым и машинно проверяемым.

## Проверки

Синтетическая поддерживаемая команда завершается. Неподдерживаемая shader operation возвращает ожидаемый диагностический статус, не вызывает silent draw-drop и не требует настоящего GPU hang. Pending compilation покрыта тестом порядка. Если меняется поведение watchdog, тест использует безопасный искусственный budget signal.

Положительный тест здесь может ожидать ошибку runtime: его test PASS означает корректную обработку ожидаемого отказа, а не успешный запуск игры. Проверки не меняют TDR registry и не отключают watchdog ради результата.

## Приёмка

Независимый reviewer перечисляет покрытые failure paths и оставшиеся gaps. GPU QA запускает только затронутые операции на точно выбранном адаптере. Политика не называется полной, пока существенные неохваченные silent paths не перечислены и не устранены для заявленного scope.
