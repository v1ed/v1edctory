# MS004 — один независимый тест семантики реального транслятора

## Цель

Проверить конкретную синтетическую AMD instruction/block последовательность через реальные decode → IR → lowering → DXIL VIctory и сравнить с независимо вычисленным результатом. Обычный HLSL→DXC тест на двух видеокартах сам по себе эту цель не выполняет.

## Выбор первого случая

Выбрать операцию/блок, для которой доступна точная спецификация и уже есть достаточно поддержки вокруг неё: например, целочисленная арифметика с wraparound или bitwise операция с определёнными исходной ISA shift semantics. Если конкретная инструкция уже покрыта, выбрать реальный uncovered edge case, не дублировать существующий тест.

Сначала посмотреть `crates/victory-shader/src/emit/semantics_tests.rs`, `host.rs` и `diff_tests.rs`. Не требовать закрытого console DXC. Для создания native fixture можно использовать существующий synthetic encoder или отдельно проверенный assembler; независимо сверить decoded opcode/operands.

## Контракт fixture

- Название и revision ISA, source URL/section, кодировка и режим wave.
- Начальные регистры/memory/active mask и входные значения.
- Независимая функция ожидаемого результата либо вручную проверенные cases.
- Правило сравнения: bit exact для определённой integer semantics; FP только с обоснованным контрактом.
- Источник fixture, seed и reproducible hash.
- Отдельно inputs, emitted shader hash, output и adapters.

Нельзя переиспользовать ту же semantic implementation в compiler и oracle. Общий decoder сам по себе допустим для некоторых тестов, но тогда decoder equivalence не проверяется и это нужно указать.

## Проверки

1. Показать failing case до исправления, если задача исправляет дефект.
2. Выполнить транслятор на synthetic source.
3. Выполнить полученный DXIL на явно выбранной RTX.
4. Выполнить на AMD как дополнительную cross-backend проверку, если поддерживаются требуемые features.
5. Сопоставить с независимым oracle и записать статус.
6. Если дефект подтверждён, внести минимальное исправление и повторить тот же case и непосредственно связанные regression tests. Если поведение уже корректно, ограничиться новым независимым тестом и фиксацией результата.

Если входной тест не требует native Xbox-специфичной hardware операции, iGPU полезна без отдельной Radeon. Если нужен raw ISA runner, выделить его в отдельное исследование, не подменять HLSL-проверкой.

## Приёмка

Тест действительно проходит через изменяемый compiler path, не пропускается и проверяет обоснованный результат. Исправление не меняет tolerances/expected output для сокрытия ошибки. Независимое ревью и GPU QA относятся к одному candidate SHA. Не заявлять универсальную эквивалентность из одного успешного теста.
