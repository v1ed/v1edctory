# MS000 — воспроизводимый baseline и инвентаризация проверок

## Цель

Установить, что реально собирается и проверяется на выбранном коммите. Задача заканчивается достоверным отчётом, который может содержать FAIL/BLOCKED; она не объявляет весь runtime корректным.

На этом этапе игровые файлы анализируются офлайн. До приёмки runtime-политики MS003 не запускать игру через `run --execute` для получения baseline или capture. Синтетические тесты, создание PSO и captures собственных минимальных приложений разрешены; их результаты не объявляются успешным рендером игры. Это выбранная последовательность разработки для требования без молчаливых пропусков, а не техническое ограничение upstream.

## Входы

- Рабочее дерево `task/MS000` от bootstrap-коммита с проектными инструкциями.
- Оригинальный upstream snapshot `940d32f69b22265690a0b5a15d6ded572ba33baf` или другой явно зафиксированный и проверенный SHA.
- Windows 11, MSVC/SDK, toolchain из repository, PC DXC/validator.
- Игровые файлы необязательны; наличие/отсутствие явно записать.

## Исполнители

`gta6-impl`: аудит исходников и сборки; `gta6-gpu`: аппаратные/потенциально GPU tests; `gta6-review`: проверка отчёта. Один исполнитель не должен выдавать собственный вывод за независимое ревью.

## Действия

1. Прочитать действующие инструкции; проверить HEAD и чистоту assigned worktree.
2. Прочитать `rust-toolchain.toml`, Cargo/CI/xtask и доступный CLI help.
3. Записать версии и хеши используемых binaries. Не писать предположенные версии вместо фактических.
4. Повторить baseline build/check/test команды. GPU-проверки согласовать с единственной QA-очередью.
5. Найти tests с prerequisite checks/early return. Отдельно указать `emit/diff_tests.rs` и необходимость `VICTORY_CONSOLE_DXC`.
6. Зафиксировать, какие тесты прошли реально, не запускались, заблокированы средой или упали.
7. При доступном корпусе выполнить offline shader inventory без исполнения игры; сохранить число отказов и примеры причин.
8. Выдать точный backlog для MS001–MS004, не менять compiler semantics.

## Артефакты

- Обезличенный текстовый baseline report в repo: SHA, команды, исходы, ограничения.
- Полные машинные логи и manifest вне repo, например `C:\gta6-lab\runs\MS000\...`.
- Заполненный по наблюдениям environment record; неизвестные поля остаются null/NOT_MEASURED.

## Приёмка

Другой исполнитель может повторить команды на той же среде. Отчёт не скрывает skipped/blocked и не подменяет test coverage успешной сборкой. Не добавлены обходы ошибок, новые FPS-прогнозы или вымышленные CLI флаги. Если обнаружена ошибка baseline, она описана как отдельная задача; широкая переработка здесь не выполняется.
