# MS002 — явный выбор адаптера и capability report

## Проблема

Shader test host выбирает первый hardware adapter с `DedicatedVideoMemory > 0`; это не надёжный выбор UMA/iGPU. Runtime default-device selection также не доказывает использование требуемого GPU. Нужен проверяемый единый контракт выбора.

## Scope

Переиспользовать существующий DXGI/D3D12 host и добавить точную идентификацию. Не писать новый полный test framework. Сначала проверить текущий `crates/victory-shader/src/emit/host.rs`, связанные callers и runtime host.

## Требования

1. Перечислить адаптеры, записать description, LUID, VendorID/DeviceID, software flag, доступную память и driver info.
2. Выбрать адаптер явно по идентичности. Если совпадений несколько или выбранный GPU отсутствует — диагностический отказ без перехода на default/WARP.
3. Не исключать UMA только потому, что dedicated memory равна нулю.
4. Получить feature level, shader model, WaveOps, min/max wave lanes, integer64 support и нужные stage/RT capabilities.
5. Поддержка Wave64 подтверждается реальным PSO и небольшим compute execution, если capability это допускает; driver reports сохраняются отдельно от наблюдения.
6. Дать WARP явный отдельный режим, исключив его случайное участие в hardware comparison.
7. Записать adapter identity и версии в machine-readable report и cache context; LUID не считать постоянным глобальным ID между любыми переустановками/перезагрузками.

## Проверки на пользовательском ПК

- AMD iGPU выбрана явно и выполняет маленький buffer-write/readback тест.
- RTX 5070 выбрана явно и выполняет тот же тест.
- Несуществующий adapter selector даёт понятный отказ.
- В output обоих успешных запусков видны разные фактические GPU.
- Неподдерживаемый wave/stage requirement даёт UNSUPPORTED, а не silent fallback.

`UNSUPPORTED` означает подтверждённое отсутствие необходимой возможности. Если устройство заявляет поддержку, но создание PSO, dispatch, синхронизация или readback неожиданно завершаются ошибкой, это `FAIL`; при установленной проблеме окружения допустим `BLOCKED` с конкретной причиной. Ошибка выполнения не превращается автоматически в `UNSUPPORTED`.

Каждый GPU получает собственные resources, результаты читаются после fence. Shared cross-adapter memory не требуется. Выполнять tests последовательно. Совпадение простого DXIL теста подтверждает работоспособность runner, но ещё не проверяет Xbox ISA translation — это MS004.
